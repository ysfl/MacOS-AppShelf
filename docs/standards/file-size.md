# 文件规模规范

只按行数衡量，不测复杂度或职责数——那两个指标在这个规模的项目里没有稳定的判定价值，
只会制造争论。

## 阈值

| 类别 | 警告线 | 阻断线 |
|---|---|---|
| `.swift` | 300 | 700 |
| `.py` | 250 | 400 |
| `.sh` | 150 | 250 |
| `.md` | 400 | 800 |
| `.json` | 400 | 900 |
| `.yml` `.yaml` | 150 | 300 |

含空行与注释，判定用严格大于。**阈值只能收紧，不能为了迁就某个大文件而抬高**——那样做
等于把规范改成对现状的追认。确实需要例外，走下面的豁免。

## 判定要看历史

同一份文件在 HEAD 里的行数和当前行数一起决定结论，否则"正在还债"和"正在加债"看起来一样：

| 情形 | 结论 |
|---|---|
| 新文件，未超 | 通过 |
| 新文件，超警告线 | 警告 |
| 新文件，超阻断线 | 阻断 |
| 历史未超 → 现在超了 | 警告（首次越线） |
| 历史已超 → 现在更超 | **阻断** |
| 历史已超 → 现在变小 | 提示（正在还债） |
| 全量扫描到未变动的存量 | 警告 |

## 豁免

写在 `Scripts/gates/exemptions.json`，每条必须齐六个字段：

`path` `check` `reason` `owner` `cap` `expires`

- `path` 必须是精确相对路径，通配、绝对路径、`..` 一律拒绝；
- `reason` 少于 12 字符，或填 `tbd` / `n/a` / `以后再拆` / `历史原因` 这类占位词，一律拒绝；
- `expires` 必须是 `YYYY-MM-DD`，过期即报错，不会静默放行；
- `cap` 是豁免期间的硬上限：文件可以到 `cap`，超过就阻断。

缺字段、类型错、日期过期，都按**配置错误**处理并阻断，而不是当作没有豁免。宁可让门禁
烦人，也不要它假装什么都没看见。

命中豁免时仍会输出一条 info，把这笔债留在台面上。

## 超了怎么办

按职责拆。拆完仍然是一个大函数，说明真正该拆的是抽象而不是文件——这时把结论写进
`docs/ledger/traps.md`，别开一条豁免把问题藏起来。
